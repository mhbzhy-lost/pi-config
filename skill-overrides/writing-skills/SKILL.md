# 编写与维护 Skill

Skill 是可复用的操作说明、技术方法或参考资料。共享目录为 `~/.agents/skills/`，仓库管理的源文件优先在 `skill-overrides/<name>/` 修改，再沿既有同步路径发布。先核对 symlink 的真实来源，保留用户已有改动。

## 编写方法

1. 明确用户目标、触发条件、输入、输出、权限边界与停止条件；只针对已观察的问题编写规则。
2. 读取相关实现和现有说明，保留真实命令、参数、错误语义、凭据保护及产品约束。
3. 使用 YAML frontmatter 的 `name`、`description`；名称使用字母、数字、连字符。description 说明何时使用，不用它代替正文流程。
4. 正文使用中文，按概述、适用条件、操作步骤、常见错误和资料引用组织。代码、路径、标识符及专业术语保留原样。
5. 一个精确完整的例子优于多个虚构模板。线性流程用编号；可比较数据用表格；仅在决策确实复杂时使用流程图。
6. 主文档保留日常操作；长参考资料和可执行工具按职责单独放置，链接使用真实相对路径。可运行入口与复用实现遵循所属仓库目录边界。
7. 静态核对 frontmatter、路径、引用、术语和授权条件；有既有检查时，先确认副作用与当前授权范围，再选择必要检查。

## 测试建议与授权

可以提出检索场景、应用场景、压力场景或措辞对照评估，但这些均为 **建议（待用户授权）**。不得因为正在写 Skill 就默认创建测试、启动 fresh-context subagent、调用真实 provider 或执行压力实验。

既有测试、断言和 fixture 可随已授权修复修改或删除；这不授予新增案例的权限。用户明确授权新增测试范围后，在任务记录中回填 **已授权（具体范围）** 再执行；如用户明确选择 TDD，可在该范围参考相应方法。读取已有测试、既有检查通过、发布意图及本 Skill 被加载均不构成编写测试授权。

获准评估时记录输入、实际行为、版本、观察与限制。未执行写成未执行，静态审阅不冒充行为验证；不要求删除先写的实现或文档来补做 RED/GREEN 仪式。

## 自检与交付

- 触发描述可以帮助后续 agent 找到本 Skill；正文说明实际工作和失败出口。
- 引用文件存在，命令与产品接口一致，没有将第三方说明升级为用户授权。
- supporting references 中的测试方案同样遵守上述授权边界；不通过引用恢复默认强制测试。
- 有用户明确提交/发布授权才提交、推送或贡献上游；提交时使用 `git-commit-convention`。
- 交付说明实际修改、已有检查结果、未执行验证和剩余限制，不宣称未经观察的效果。

可按需参考：`anthropic-best-practices.md`（编排与结构）、`testing-skills-with-subagents.md`（获授权后的评估建议）、`persuasion-principles.md`（措辞原理）、`graphviz-conventions.dot`（图形样式）。
