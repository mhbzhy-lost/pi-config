# 获授权后的 Skill 评估参考

本文件描述可选的 Skill 使用评估方法。它不要求默认运行 subagent、fresh-context pressure scenario 或先写失败测试。只有用户明确授权具体评估范围后，才可执行相应场景，并在记录中写明“已授权（范围）”。

## 评估前

- 明确要观察的行为、版本、输入、资源和停止条件。
- 记录 Skill 的触发条件和预期输出形状。
- 未授权时只做静态阅读、路径核对和已有检查，不能把建议写成已执行。

## 获授权后的可选步骤

1. 使用一个与实际使用相同的上下文运行公开入口。
2. 记录实际选择、输出、偏离点和完整事件顺序。
3. 若需要对照，分别说明是否加载 Skill；不要把单次样本外推成稳定行为。
4. 根据已观察缺口修改 Skill，再执行用户授权范围内的复核。
5. 记录未覆盖的 provider、Host、网络、凭据、并发和压力条件。

## 结果记录

区分静态合同、已有检查、获授权行为验证和未执行建议。测试失败先做 provenance 分类；没有证据证明 production 可达时，不增加 fallback 或兼容分支。真实 provider、网络安装、Host/PTY、危险进程和跨进程实验分别需要相应资源授权。

“压力测试”“TDD”“RED/GREEN”“fresh-context”都是可选方法名，不能作为 Skill 编写、Skill 修改或普通 coding task 的默认门禁。
