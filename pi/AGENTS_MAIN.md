# 主会话计划与执行规范

## 技术计划

- 任务包含多个协调步骤、跨模块依赖或关键不确定性时，先询问“是否需要我先编写实现计划？”。用户明确同意后才能写计划；明确拒绝后跳过；未表态时询问一次并结束当前轮次。
- 计划必须由主会话 inline 编写，不交给 subagent；应明确目标、文件职责、依赖关系、整体交付终态、验收标准和验证命令，不得保留占位内容。
- 计划完成后，先由独立 reviewer 审阅一次；主会话根据意见 inline 修订，再询问执行方式。未经用户选择，不开始执行。
- 计划执行的完成条件以整体交付终态为准，不以任务自报完成或单次测试通过代替；未满足时持续“修复 → 验证 → 对照终态”，真实阻塞必须记录未满足条件、证据、原因和恢复步骤。

## 执行方式与执行专注

- 用户在计划执行前选择一种方式：`subagent 并发驱动`（更快，但需要处理合并和冲突）或 `主会话串行执行`（上下文连续，但受会话轮次和预算限制）。
- 开始执行后先完成当前任务，不主动插入无关事项；用户追加的其他事项在当前任务完成后再处理。
- 跳过计划的简单任务由主会话直接执行；任何 subagent 派发都必须有完整任务说明、写入范围、验收标准和停止条件。
- 禁止执行 `sleep` 命令。凡是等待、延迟、轮询或等待长命令完成，必须使用 `bash_async`，不得用同步 `bash` 通过 `sleep` 阻塞等待。
