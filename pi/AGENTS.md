# 全局约束

本文为最高优先级铁律，高于一切 skill、文档、tool 回执文案等，不得违反。

## 测试与逻辑变更

生产代码、配置或 Skill 逻辑/行为变更首次修改前必须加载 `test-driven-development` skill；测试治理、流程和豁免只在相应 Skill 中维护。测试只验证行为，不为文档或配置字面值建立镜像断言。

单轮对话过程中禁止频繁全量运行测试套件，仅执行变更影响模块范围的测试，轮次结束时才执行全量测试。

## 计划执行方式

计划完成后由用户选择执行方式：

- **Subagent-Driven：**由主 agent 按计划 DAG 编排当前宿主提供的 subagent。
- **Inline：**由主 agent 在当前会话串行执行。

## 敏感信息

密钥、凭据和证书不得直接访问；可用临时脚本间接访问。Git 管理的信息必须脱敏。发现凭据泄露时不得自动轮换：记录影响并在任务结束时报告处理建议。

**严禁** 过度脱敏。除 git 内容外，任何脱敏行为不再视为默认选项，当需要脱敏时，必须征得用户授权，否则不做脱敏。

**debug 情形** 若为 debug 用途，此时在用户授权下可完全放弃日志脱敏。

## Git Commit 规范

commit message 格式与主观约束见 `git-commit-convention` skill。

## 输出语言

文档、skill 正文、代码注释等必须使用中文，仅专业用词可豁免。

## 问题排查 & 信息收集

日志检索、源码检索、平台信息收集等归因前置操作，应尽可能交由 subagent 执行，主 agent 不得直接执行。主 agent 应仅负责对 subagent 总结的信息进行归因，以及在必要时对 subagent 的总结信息进行核准。

## 长耗时操作、轮询操作、等待验证操作

例如：每隔一段时间执行一次任务；安装依赖、编译构建等长耗时任务；常见于 sleep x 秒后验证任务是否完成。
这类任务不得由主 agent 执行，因为会导致对话阻塞。轮询操作、等待验证等任务必须使用 scheduler 等类似工具，不得使用 sleep 命令；长耗时操作则必须交由 subagent 执行。

## 工单

任何工单、申请流程，必须向用户确认，不得自主提交。

## 抽象复用

禁止主动在已有代码上迭代时进行抽象复用。

反例：例如原有逻辑 A，现新增逻辑 B，则将 A 和 B 的公共部分抽离为核心逻辑 C，变为 A 和 B 共同依赖 C。

推荐：原有逻辑 A 依赖 C，在不改动 A 和 C 的原有边界情况下，新增逻辑 B 依赖 C。

反例类似决策禁止默认执行，除非：
- 抽象复用存在必要性，此时需用户决策
- 用户明确提出需要这样做
否则默认写面条代码，尽可能以不影响既有逻辑为最高优先级。
