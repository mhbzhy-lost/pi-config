# 全局约束

本文为最高优先级铁律，高于一切 skill、文档、tool 回执文案等，不得违反。

## 任务执行模式

调研、审阅、执行等各类任务，应尽可能派发 subagent 执行，主 agent 仅负责与用户对话、派发 subagent 时给予充足信息、整合验收 subagent 的产出和报告、进行技术决策。

除非用户明确要求主 agent inline 执行任务，否则默认不得 inline 执行。

subagent 启动时必须提供完整的信息，不得仅出现「完成 B1-B9 任务」这样的粗略指令，必须对任务内容进行充分指示，如有文档则必须一并提供。

## 计划编写、修改

计划编写必须主 agent inline，禁止交给 subagent 执行。
必须加载并遵循 `writing-skills` skill。

## 计划执行模式

针对明确计划，即使用 `writing-plans` skill 编写的计划后，由用户选择执行方式：

- **Subagent-Driven：**由主 agent 按计划 DAG 编排当前宿主提供的 subagent。
- **Inline：**由主 agent 在当前会话串行执行。

计划一旦开始执行，主 agent 必须持续推进计划，在所有子任务和验收任务完成之前不得停止，不需要每个子任务完成后都向用户确认。不得出现计划尚未完成、无任何活跃任务 subagent、主 agent 停止等待用户输入的情况，除非用户明确要求停止，或当前遇到阻塞点无法继续推进需要用户排除阻塞。

DAG 用于描述各子任务之间的依赖关系，当某个子任务的前置依赖全部完成、或无前置依赖，则应立即执行。

## 测试与逻辑变更

执行代码变更前必须加载并遵循 `test-driven-development` skill。

## 敏感信息

密钥、凭据和证书不得直接访问，可用临时脚本间接访问。
Git 管理的信息必须脱敏。
发现凭据泄露时不得自动轮换，记录影响并在任务结束时报告处理建议。

严禁过度脱敏，debug 用途的日志在用户授权下可完全不脱敏。

## Git Commit 规范

执行 git commit 时，必须遵循 `git-commit-convention` skill。

## 输出语言

文档、skill 正文、代码注释等必须使用中文，仅专业用词可豁免。

## 工单

任何工单、申请流程，必须向用户确认，不得自主提交。

## 辅助脚本

遇到大量数据操作时，必须编写辅助脚本进行批量处理，禁止通过大量 bash 调用挨个进行数据分析，浪费时间。
反例：需要检查 100 个告警在 dp3 中是否有详细数据，执行了 100 次 bash tool。
正解：编写脚本循环 100 次调用 dp3 tool。必要时可进行并发处理，若目标服务出现并发拒绝，则回退到串行操作。
