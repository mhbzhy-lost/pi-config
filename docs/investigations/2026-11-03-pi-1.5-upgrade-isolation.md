## 安装脚本与 lifecycle 的精确边界

`node scripts/setup-subagent-runtime-deps.ts --check-upgrade` **是真实存在的入口**：脚本 `:69-75` 明确解析 `process.argv.includes("--check-upgrade")`，只调用 `assertSafeSubagentRuntimeUpgrade()`。`:23-28` 仅在 installed upstream version 与目标常量不同且 `PI_ROOT_SUBAGENT_BROKER_ENABLED === "1"` 时拒绝；缺安装、版本相同或 marker 不为 1 均可返回。它不枚举进程/socket，不能证明没有其它活跃 Host，也不是完整升级检查。

根 setup 默认路径由脚本 import.meta.dirname 定位，不靠 cwd 决定目标；必须使用 candidate 内的脚本，单单在 candidate cwd 调用主仓脚本仍会写主仓。未传 `--check-upgrade` 会卸载 pi/npm 旧包、安装增强依赖、运行 setup:runtime/verify:package，再安装 scheduler 与 TypeBox，确有写入和网络副作用。

增强包 `scripts/setup-runtime-deps.ts:11-21` 的步骤：

1. 官方 registry `npm install --ignore-scripts --omit=peer --save-exact pi-subagents@0.80.0`（当前常量，尚未升级）。
2. macOS/Linux 显式 `npm rebuild fs-ext --ignore-scripts=false`。
3. 用当前 `process.execPath` 验证 `require('fs-ext').flock` 为函数。
4. 若 PI_HOST_ROOT 存在，调用 `bindPhysicalHostPeers()`。

所以 **fs-ext 是该脚本唯一显式放行的 dependency lifecycle**，并且需要 Node ABI 加载验证；不能扩大成“整个 Pi 1.5 闭包唯一需要生命周期”。当前两份 lock 还标有 `@google/genai` 与 `protobufjs` 的 hasInstallScript，目标闭包未安装、这些脚本必要性未核对。根 setup 的 scheduler 安装也没有统一 --ignore-scripts；不能把全量 setup 当“只 rebuild fs-ext”。本轮没有运行 install/rebuild。

`init-pi.sh` 还写 shell 配置、调用 `uv tool install --force basic-memory`、同步 skills/settings、执行 npm test/doctor/integration，不能拿来直接初始化隔离候选。`verify-package.ts` 会 npm pack 官方包并核对 SHA-256/发布闭包，既不是纯离线测试，也不是本轮已运行项。
