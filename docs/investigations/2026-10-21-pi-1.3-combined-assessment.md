## 1. 结论

本次按一个整体升级窗口处理，但范围收窄为：

1. Pi 四个核心包升级到 `1.3.0`。
2. `pi-subagents` 精确升级到 `0.79.2`：旧版对 chord/旧 Host 的假设会阻碍干净安装，且 0.79.x 的恢复、通知、嵌入 Host 选择修复与本仓运行面直接相关。
3. **scheduler 不升**，保持 `@amaster.ai/pi-task-scheduler@0.1.9`、`@amaster.ai/pi-shared@0.1.9`、`croner@10.0.1`。`0.1.29` 没有修复并发、缓存、Lock 或 owner 隔离问题，却会让当前 adapter 的 `list/get` 因 `details` 结构化结果直接硬失败；并入本次会把两个独立变量混在一起。
4. **冻结 1.0.4 补强**：1.0.4 上的低影响遗留项不为它们单独补强；升级只做必要兼容。回归只验证它们没有被新版放大，并把确实属于目标版的新风险纳入同一轮验收。
5. **保留本仓能力**：不因上游出现名称相似的 `resume`、session succession、session lease、process-terminal、completion notice 或 physical Host 选择，就删除本仓的 root broker、workspace/queue/proof、session-owner、supervisor 控制面、typed tools 或 heartbeat。函数级证据表明这些语义不等价。
6. **不重复建 sender**：完成通知的投递、wake、Esc hold、同进程 pending notice 重放与通知级 dedupe 使用 `pi-subagents 0.79.2` 的实现，不再新建第二个 completion sender。
7. **F8 不作为升级前置**：此处指 `F8(作)` 五-child「主 Agent 接管」（即 `outstanding-items.md` `C1` 的 typed resume → workspace queue activation；与 `F8(悬)` 的 heartbeat 正常结算无关）——它是同版本存在的能力缺口，主症状已由同 Host recovery 快路径闭合，不先修这条接管链再升级。

没有发现“升级后可以直接删除一整块自建能力”的证据（上游核验可删除项为 0）。可退役的只有没有生产消费链的观测/死路径，且应作为独立清理，不与版本升级混写。

## 3. 必须保留的本仓能力（名称相似 ≠ 语义等价）

### 3.1 继续使用上游能力

- 完成通知的投递、wake、Esc hold、同进程 pending notice 重放、通知级 dedupe：用 `pi-subagents 0.79.2` 的实现，**不新建第二个 completion sender**。
- 机器可读的 run 关联优先用上游 `details.runs[]`，不解析通知正文；但这只替代文本关联方式，不能替代本仓 receipt、proof、owner 或幂等重放。
- 0.79.1 的 child 优先使用嵌入应用真实 Pi、0.78+ 的 chord 条件化，减少旧 physical peer 启动假设；本仓的 physical Host 版本/同源校验仍必须保留。
- Pi 1.3.0 的 transcript 工具恢复、0.78 的工具声明 pinning、0.79.2 的 completion 持久重放作为新版行为验收面，不再另造同类基础机制。

### 3.2 必须保留本仓实现

- `subagent_start` 与 `subagent_run_*` 的 typed、model-only 工具面：上游仍主要提供 union `subagent`，不能替代本仓的操作合同与工具暴露边界。
- root broker、root/session owner receipt、terminal proof、authority grant、supervisor replay 与消费核对：上游 process-terminal 只证明 runner 退出，不证明本仓的 root/run/owner/lease/publication 条件。
- managed workspace service、coordinator、integration queue、disposition settlement、publication CAS 与 proof outbox：上游 `resume` 只恢复 child 会话、模型、cwd/worktree，不知道本仓 queue/admission/publication/lease。
- `src/session-owner/**`：Pi 1.3.0 没有本仓需要的跨进程 session 单写者锁；上游 session lease 是 child revival 作用域。
- heartbeat 与父死拓扑证据：上游没有等价的父存活检测合同。
- scheduler adapter 的四工具白名单、model-only、敏感/注入/Unicode 扫描、owner/epoch、observer 三态、routing context 与 `expandPromptTemplates:false`。
- `ActivityRow.metaLabel` 与 footer/TUI 自建承载：新版 TUI 的 APC 光标、滚轮、overlay 输入路径反而需要复验，不能提前删除自建 renderer。

### 3.3 只允许在证据充分后退役

- 两个未跟踪 observation 文件：无生产消费，会被 integration glob 自动执行，应移出或移到 `scripts/probes/`；属独立现场清理，不带入升级 checkout。
- `scripts/probes/dispatch-branch-probe.ts` 的 dead action 分支。
- `resolveTargetChild`：当前无生产调用方且 `complete` 无公开证明；保持死码比放宽前置安全。
- `src/compat/pi-subagents-0.75.ts` **不应删除**：它有 3 条生产消费链；升级后最多改名去掉版本号，并同步 package 规范。
- `legacy-executor-compat.ts` 仍读取 v1 grant/proof，只有确认旧现场不需读取后才能另立清理。
