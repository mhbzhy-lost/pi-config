# Pi 1.0.2 + pi-subagents 0.75.0 联合升级审计结论

**目标组合：** Pi 四核心包 `1.0.2` + pi-subagents `0.75.0`。旧生产组合 `0.87.1 + 0.71.0` 保持不变。用户要求自主推进至联合升级方案；不把方案授权解释为全局切换、commit、真实模型费用或工单许可。

## 结论

选择1.0.2而非1.0.0的条件成立：没有发现额外必需的本仓production适配。新增字段为可选，现有API消费未见删除；A6 argv修复仍适用。**复验成本不为零**，尤其1.0.2取消npm-shrinkwrap，必须重新固定实际依赖闭包。当前生产仍NO-GO，加载身份、child权限及真实生命周期证据未完成。

## 已证事实

- 四core1.0.2同gitHead `cd32f7725fdbddbaecdff5b1e68491563394e0ca`，Node下限仍>=22.19.0。
- 1.0.1增加brace-expansion5.0.12安全pin及codemode OOM修复；1.0.2增加可选samplingParamsByThinkingLevel。
- 不提供samplingParamsByThinkingLevel时不会自动增加per-level采样表。外部provider新增wire行为仍须复验，不能把没有必改代码写成全面兼容。
- 1.0.2仍无pi-agent-core/node导出。subagents0.71–0.74含两个patch都无条件要求该alias；0.75是已核验区间内最小解除门禁的版本。
- 0.75将该alias标optional：公开exports不能解析时跳过，已解析但文件损坏仍拒绝。不是删安全检查。
- 0.75 publicRPC拒绝workflowScript，要求script；本仓workflow-spawn必须迁移wire字段。内部载体仍可能叫workflowScript，禁止不分入口全局替换。
- 0.75默认单child execution timeout仍30分钟，本仓2147000000ms小于2147483647上限；必须验证真实leaf/resume，不回退该已批准策略。
- 0.75required session_start异常更严格；不自动恢复ended-child auto-resume，不改变workspace/proof authority。
- 0.75宽默认child tools可装入codemode；不主动调用或仅关闭主Host不构成child权限隔离。
- optionalalias不证明embedded/native/absolute child namespace同实例。尚无已证public child SDK注入接点；不能vendor、泛resolver、深import修复或放宽Doctor。

## 原1.0.0候选证据边界

候选 `/tmp/pi-100-upgrade.Nxvr1T`：Node22.19.0官方SHA核验成功，完整core/subagents0.71闭包建立。bundle版本最初误报0.87源于ambient PI_PACKAGE_DIR，白名单环境正确1.0.0。

A2双Node8项5pass3fail，watchdog/nativeSessionManager身份精确RED，absolutechild使用physicalSDK；A3双Node3/3只证明官方SDK显式tools ceiling，不证明当前production接线。A6双Node31/31与无socketshutdown8/8，A7双Node40/40，独立review通过窄合同。**以上不结转为1.0.2+0.75运行GREEN。** 保留原候选对照，所有新测试明确artifact、Node和环境。

## 范围和决策

本次方案采用保守现有产品基线：不恢复Goal/auto-continuation/ended-child自动resume，不捎带scheduler/shared0.1.9、croner10.0.1、scheduler typebox1.1.38、BasicMemory0.22.1升级。不开放MCP/codemode/tool_search/llama.cpp/virtual/image/classifier新能力，控制面建议model-only并实际验证registry ceiling。该策略是本轮方案的技术选择，不声称此前产品许可已经存在；实现方案时应按明确scope执行，偏离scope须重新评审而非静默扩权。

未来Goal R0–R13仅合同映射，主线已移除Goal；blocked inventory/replay/scheduler recovery不借升级接线。TokenStats/仓外trace缺源码范围保留未覆盖，不宣称全面兼容。

## 成本

联合现有能力确定适配/隔离验证约7–13人日，加载/child公共接点探索2–5人日，加集成缓冲后预算10–20人日。1.0.2对1.0.0未发现额外必改production代码，重新安装锁闭包与目标复验需纳入这段预算，不能机械叠加估算。公开接点探索可提前得到NO-GO，不保证最终发布。
