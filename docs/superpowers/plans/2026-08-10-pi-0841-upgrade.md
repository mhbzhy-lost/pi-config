# Pi 0.84.1 升级实施计划

> **供执行型 Agent 使用：** 必须先加载并遵循 `test-driven-development`；编码任务通过 `subagent-dispatch` 派发。步骤用复选框记录进度。

**目标：** 在不升级 `pi-subagents` 的前提下，将全局 Pi 与本仓可复现安装策略从 `0.83.0` 升级到 `0.84.1`，并通过现有 Pi、RPC 和子代理回归门禁。

**架构：** 保持 `pi-subagents@0.37.2` 与 `typebox@1.1.38` 不变，只扩大项目允许的 Pi 精确版本集合并将新机器默认安装版本固定为 `0.84.1`。先用临时 npm prefix 验证真实 Pi 运行路径，再替换全局安装；所有仓库版本策略均由测试先行锁定。

**技术栈：** Node.js 22.19+、npm 官方 registry、`@earendil-works/pi-coding-agent@0.84.1`、Pi JSONL RPC、Node 内置 test runner。

## 全局约束

- 目标 Pi 版本精确为 `0.84.1`，不接受宽松的 `0.84.x`。
- `pi-subagents` 必须保持 `0.37.2`，`typebox` 必须保持 `1.1.38`。
- 不修改 `pi/settings.json`：它已有用户未提交改动；尤其不覆盖 provider、model、package 或 `lastChangelogVersion` 字段。
- 不读取、复制或输出 `pi/auth.json`、npm 凭据或任何认证文件。
- 不操作现有 Goal、`.state/worktree-lifecycle/` 或受管 worktree。
- 全局安装仅使用 `https://registry.npmjs.org`，不改写用户全局 npm registry。
- 历史计划、历史缺陷文档中的旧 Pi 版本是历史证据，不做追溯性改写。

## 文件职责

- `scripts/probes/pi-subagents-compat.mjs`：定义 Pi 与固定 `pi-subagents@0.37.2` 的允许版本契约。
- `scripts/doctor.mjs`：在真实 `pi --version` 上执行同一允许版本策略。
- `test/pi-subagents-compat.test.mjs`：锁定兼容报告接受 `0.84.1`、拒绝未列出的版本。
- `test/doctor.test.mjs`：锁定 Doctor 对 `0.84.1` 的接受及错误消息。
- `init-pi.sh`：新机器唯一初始化入口，安装精确 Pi 版本。
- `test/init-pi.test.mjs`：验证初始化脚本从官方 registry 安装精确 Pi 版本且不读取凭据。
- `README.md`：面向维护者说明默认安装版本和已验证组合。
- `test/pi-runtime.integration.mjs`：保留真实 Pi runtime 的诊断文字与支持版本策略一致。
- `docs/bugs/bug-pi-compat-probe-assumes-homebrew-prefix.md`：记录兼容探针不得假定 npm 全局安装前缀的根因与回归边界。
- `docs/superpowers/plans/2026-08-10-pi-0841-upgrade.md`：本次实施与验证边界。

### 并行调度组

- **Wave 1（可并行）**：T1、T2。二者没有共同写入路径；T1 只处理兼容策略，T2 只处理初始化和说明。
- **Wave 2**：T3。依赖 T1 产出的 `0.84.1` 允许版本契约，避免候选运行被旧门禁误判。
- **Wave 3**：T4。依赖 T1、T2、T3；只有候选运行已验证后才替换全局 Pi。
- **Wave 4**：T5。依赖 T4 的最终安装状态和回归结果。

## 实施偏差记录

Pi `0.84.1` 候选的基础 RPC 与子代理集成门禁通过后，全量测试暴露两个真实宿主变化：`TUI` 由可构造导出变为 type-only 符号，以及 reload 时旧 extension context 和 event facade 被失效。没有将这些失败归因为既有 Goal 基线或改弱测试；已按 TDD 补充 `TuiMainScreen` 输入夹具，并把 shutdown debt 的跨 generation 身份绑定到稳定的 `sessionManager`，重试时使用新 context。随后外源审查还识别出浏览器兼容探针静态依赖 Homebrew 前缀；已以临时 npm 全局根目录的真实模块导入测试改为按需解析。根因和验证边界见 `docs/bugs/bug-pi-0841-tui-and-reload-compatibility.md` 与 `docs/bugs/bug-pi-compat-probe-assumes-homebrew-prefix.md`。
