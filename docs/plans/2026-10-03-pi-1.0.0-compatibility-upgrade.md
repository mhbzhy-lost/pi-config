# Pi 1.0.0 建设合同兼容升级实现计划

> **已被取代（2026-10-04）：** 当前目标已确定为 `Pi 1.0.2 + pi-subagents 0.75.0`，实施入口改为 `docs/plans/2026-10-04-pi-1.0.2-subagents-0.75.0-joint-upgrade.md`。本文及A0–A7证据仅保留历史对照，不再按本文固定0.71版本派发新升级任务；旧候选不可将结果结转为联合目标GREEN。

> **给执行 agent：** 必须逐任务执行本计划；步骤使用 `- [ ]` 复选框跟踪。执行方式由计划完成后的用户选择决定。

**目标：** 完成可复核的 Pi 1.0.0 隔离候选、建设合同兼容验证与升级决策；只有公开加载接点、child 权限接点、最低 Node 和真实验收成立，才冻结生产修复任务并申请切换。

**架构：** 保留 typed dispatch、Root Broker、workspace/proof 和 scheduler owner。按用户明确要求，在 `/tmp` 下的一次性隔离代码树和依赖环境完成适配与测试，通过后将已验收的源码、测试、文档与 lockfile 改动合回主目录；不创建长期 `pi-config-upgrade` 仓、不新增 `pi-new` 或其他试用入口。升级分为已可执行的取证与兼容切片，以及受硬门禁约束的生产适配/切换；不得用临时 resolver 原理探针替代已证公共 composition，也不为未来 Goal 或 blocked registry 伪造当前实现。

**技术栈：** Node 原生 TypeScript，最低 `>=22.19.0`；Pi core 四包 `1.0.0`；固定 pi-subagents `0.71.0`、scheduler/shared `0.1.9`、croner `10.0.1`、scheduler typebox `1.1.38`、Basic Memory `0.22.1`；node:test、tsc、官方 bundle/SDK、隔离 dependency closure、PTY。

## 全局约束

- 计划编写必须主 agent inline，禁止交给 subagent 执行。
- 执行代码变更前必须加载并遵循 `test-driven-development` skill。
- 密钥、凭据和证书不得直接访问，可用临时脚本间接访问。
- Git 管理的信息必须脱敏。
- 发现凭据泄露时不得自动轮换，记录影响并在任务结束时报告处理建议。
- 文档、skill 正文、代码注释等必须使用中文，仅专业用词可豁免。
- 任何工单、申请流程，必须向用户确认，不得自主提交。
- 仓库和 package 的最低 Node 版本固定为 `>=22.19.0`。
- `scripts/` 只放可直接执行的 CLI、初始化脚本和诊断探针；可复用实现不得新增到 `scripts/`，production 模块不得新增对 `scripts/**` 的 import。
- Node 原生可执行的 production/CLI 代码统一使用 `.ts`。
- `scripts/lib/` 是待迁移的历史目录，不是共享基础库。禁止在其中新增文件、扩大依赖或把新调用方接入其中。
- `pi/extensions/` 只放 Pi 自动发现入口及其入口级配置。
- 所有面向用户的精简、折叠、摘要、截断和换行只能发生在 TUI renderer 层。
- `enabledModels` 字段为 per-machine 配置，禁止提交其变更。
- `pi/models.json` 是本机配置，不读取原文、不提交、不同步。
- R0–R13 全部完成并通过 R13 验收前，禁止使用 Goal Engine 执行、编排或验收该改造计划；冻结 planned-goal 不阻塞 R1–R13。
- 本计划不恢复主线 Goal、不恢复 ended-child 自动 resume、不启用 auto-continuation，不接 blocked inventory/recovery，不清历史 proof debt 或旧 state。
- 不修改 `planned.v1`、历史 generation、typed dispatch IR、terminal proof 或 workspace authority。
- 失败先记录数据来源、首个偏离点与完整生成链，按 production / fixture / unknown 分类；unknown fail closed，不加预防性 fallback。
- 用户已明确执行拓扑：在 `/tmp` 临时隔离目录适配与测试，通过后合回主目录；不做试用入口。此授权不等于真实模型费用、全局切换或 commit 授权；执行方式与具体能力范围在A0记录，旧升级授权不得复用。
- 不默认提交；另获授权后才加载 `git-commit-convention`。

- Wave0：A0；Wave1：A1；Wave2：A2–A7并行；Wave3：D0；Wave4：B1；Wave5：B2；Wave6：B3。
