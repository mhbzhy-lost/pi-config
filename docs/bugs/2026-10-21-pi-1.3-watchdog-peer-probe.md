# Pi 1.3.0 迁移后 physical Host 探针的 watchdog 身份谓词失效

## 现象

`pi-subagents` 升级到 `0.79.2`、Pi Host 升级到 `1.3.0` 后，physical Host 探针把健康的运行时判为不一致：

```text
[error] physical identity不一致: {"version":"1.3.0","healthy":false,"identities":{"SessionManager":true,"Container":true,"Agent":true,"streamSimple":true,"watchdog":false}}
```

受影响的入口与门禁：

- `npm run doctor`（`scripts/doctor.ts:464` → `probePhysicalHost`）exit 1；
- `test/joint-upgrade-host-probe.test.mjs:14`（断言 `identities` 五项全 `true`）；
- `test/joint-upgrade-loader.test.mjs`（旧断言 `component.constructor === ids.host.Container`）；
- `test/fixtures/doctor-pi-peer-probe.mjs`（旧 `host.Container` 身份断言）与消费它的 `test/doctor-pi-peer-runtime.test.mjs`。

来源：`/Users/leshi.zhy/pi-upgrade-1.3.0/reports/acceptance-1.3.0-verification.md` 第 5 节缺陷 A（阻塞）与缺陷 B（迁移漏改的旧断言）。

## 数据来源与分类

该异常属于「**预期 production 数据未被正确处理**」：探针拿到的是 upstream 合法返回值，问题在探针自身对类型的判断。

- 实际入口：`packages/pi-subagents-enhanced/src/host-runtime/index.ts`（生产探针，doctor 与 host-probe 共用）；
- 权威事实：`pi-subagents@0.79.2` 注册的 `subagent_watchdog_warning` renderer 的真实返回对象；
- 差异点：探针要求该返回值「直接由 Host 的 `Container` 构造」，而 0.79.2 返回的是 `Box` 子类。

诊断实测（`/Users/leshi.zhy/pi-upgrade-1.3.0/logs/acceptance/08-watchdog-identity-diagnostic.log`，status 0）：

```json
{
 "registered": true,
 "types": ["subagent_watchdog_warning", "subagent_watchdog_clarification"],
 "constructorName": "SubagentMessageBlock",
 "instanceofHostContainer": false,
 "instanceofHostBox": true,
 "enhancedContainerEquality": true,
 "resolvedTuiPaths": {
  "enhanced": "/Users/leshi.zhy/pi-upgrade-1.3.0/repo/node_modules/@earendil-works/pi-tui/dist/index.js",
  "host": "/Users/leshi.zhy/pi-upgrade-1.3.0/repo/node_modules/@earendil-works/pi-tui/dist/index.js"
 }
}
```

即：模块单实例属性仍然成立（`Container === enhanced`、两端同一 realpath），失效的只有「renderer 必须直接构造 Host `Container`」这一旧谓词。

## 首个偏离点

`pi-subagents@0.79.2` 把 watchdog 消息并入统一消息渲染路径：

- `packages/pi-subagents-enhanced/node_modules/pi-subagents/src/extension/index.js:545`：`pi.registerMessageRenderer(customType, renderSubagentMessage)`；
- `.../src/tui/subagent-messages.js:262`：`renderSubagentMessage` 返回 `new SubagentMessageBlock(...)`；
- `.../src/tui/subagent-messages.js:222`：`class SubagentMessageBlock extends Box`；
- `node_modules/@earendil-works/pi-tui/dist/components/box.js:6`：`export class Box {`（不继承 `Container`，1.0.4 与 1.3.0 相同）。

旧版本 `0.75.0` 走的是 `src/watchdog/register-main.js:363` → `src/watchdog/render.js:41 new Container()`，所以旧断言当时成立；该断言在 0.79.2 上已不再是合法目标。

## 完整调用链

```text
npm run doctor / test/joint-upgrade-host-probe.test.mjs
  -> scripts/doctor.ts:464 probePhysicalHost()
  -> packages/pi-subagents-enhanced/src/host-runtime/index.ts（spawnSync node --input-type=module -e …）
  -> sdk.discoverAndLoadExtensions([probe-extension.ts])
  -> probe-extension.ts physicalIdentityProbe() -> upstreamSubagentRuntime(pi)
  -> pi-subagents 0.79.2 src/extension/index.js:545 registerMessageRenderer(subagent_watchdog_warning, renderSubagentMessage)
  -> probe 调用 messageRenderers.get('subagent_watchdog_warning')(…)
  -> src/tui/subagent-messages.js:262 new SubagentMessageBlock(…)
  -> 旧断言 component.constructor === tui.Container 为 false（实际为 Box 子类）
  -> identities.watchdog=false -> healthy=false -> "physical identity不一致"
```

## 修复

只改断言谓词，不放宽检查、不取消检查：

1. 生产探针 `packages/pi-subagents-enhanced/src/host-runtime/index.ts`：`watchdog` 改为
   `component instanceof tui.Box && component.constructor !== tui.Box`，即「真实的 physical Host `Box` 子类，且不是裸 `Box`」。
   - `instanceof Host Box` 仍然证明 upstream 消费的是 Host 的 `pi-tui` 模块实例（异源副本会 `false`）；
   - `constructor !== Host Box` 保留旧断言的严格性，排除 renderer 退化为裸 `Box` 的情况；
   - `SessionManager` / `Container` / `Agent` / `streamSimple` 四项既有 identity 检查逐字保留，`identities` 键名与 `healthy` 语义不变（`test/joint-upgrade-host-probe.test.mjs` 的 `deepEqual` 契约不变）。
2. 同根因 fixture `test/fixtures/doctor-pi-peer-probe.mjs`（watchdog-consumer 模式）：改断言 `component instanceof host.Box / local.Box` 且 `component.constructor !== host.Box / local.Box`，并同步更新其 stdout 说明文字；四包版本与模块共享断言保留。
3. `test/doctor-pi-peer-runtime.test.mjs`：watchdog 用例改为匹配上述 stdout，两处「all four `1.0.4`」文字断言迁移到 `1.3.0`（fixture 已输出 `1.3.0`）。
4. `test/joint-upgrade-loader.test.mjs`：`--probe` 分支改为对照 Host `pi-tui` 的 `Box`（`path.join(hostRoot, '..', 'pi-tui', 'dist', 'index.js')`）作 `instanceof` + 非裸 `Box` 断言，并补回 `ids.host.Container === hostTui.Container` 的 loader 同源对照，保留 `nativeSessionEqualsHost` 这一真实 physical peer 身份断言。

未修改上游 `pi-subagents`，未引入任何 any-version/宽泛 fallback，未改动其他模块。

## 修复边界与残余风险

- 断言语义为「Host `Box` 子类」，不钉死具体类名（`SubagentMessageBlock`）。若 upstream 改为返回非 `Box` 组件（例如另一个根组件类型），探针会继续 fail closed，需要重新核对 upstream 实际类型后再迁移，不得放宽为 `typeof component.render === 'function'` 之类形状检查。
- 本次修复未运行测试、未跑 Host、未 typecheck；仅做 `git diff --check` 与静态核对。待验证命令：
  - `npm run doctor`
  - `node --test test/doctor-pi-peer-runtime.test.mjs`
  - `node --test test/joint-upgrade-loader.test.mjs`
  - `node --test test/joint-upgrade-host-probe.test.mjs`
  - `npm run typecheck`
