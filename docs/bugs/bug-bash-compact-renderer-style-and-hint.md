# Bug: Bash 紧凑渲染省略号失去背景且缺少展开提示

## 现象

Bash Tool 折叠后能够保持单行，`Ctrl+O` 也能展开，但长命令末尾的 `...` 没有 Tool 行背景色，折叠态也没有显示 `Ctrl+O to expand` 提示；展开后命令标题仍然保留截断省略号。

## 影响

省略号形成明显的背景断层；用户无法从界面发现 Bash 输出可以展开，容易误以为输出已被丢弃或展开功能失效。

## 根因

紧凑 renderer 先对已包含 ANSI 前景样式的命令调用 `truncateToWidth()`。该函数会在省略号前插入 `\x1b[0m`，这同时清除了外层 Box 设置的背景色，因此随后追加的省略号不再继承背景。renderer 也没有使用 `app.tools.expand` 的标准 key hint，并且 `renderCall` 忽略 `context.expanded`，导致展开态仍使用单行截断组件。

## 促成因素

1. 单元测试使用无 ANSI 的 fake theme，无法发现样式重置问题。
2. 测试只验证手工传入 `expanded: true` 能显示输出，没有验证折叠态的交互提示。
3. 为追求严格单行，result renderer 被设为空，但没有把展开提示合并进 call 行。

## 修复方向

折叠态先截断未着色文本，再对包含省略号的完整结果统一着色，避免省略号前出现 ANSI reset，并在同一行内为标准 expand key hint 预留宽度；展开态改用可换行的完整命令组件，不做截断。

## 防复发

增加带 ANSI theme 的断言，确保省略号位于最终样式闭合序列之前；增加折叠态提示测试，并继续断言整个折叠 Tool 只有一个视觉行。
