# writing-plans 将未表态静默当作拒绝并直接执行

## 问题

复杂、多步骤、跨模块或存在关键不确定性的任务会命中 `writing-plans` 的 frontmatter `description`，但用户既未明确同意也未明确拒绝编写计划时，Skill 当前把该状态直接归入“跳过计划创建，直接执行”。因此 agent 不会主动询问计划授权，可能直接开始实现或派发。

## 真实数据来源

- 生产规则来源：`skill-overrides/writing-plans/SKILL.md` 当前 frontmatter 第 3 行的宽触发 description，以及“用户授权门禁”段落。
- 运行时行为来源：五个 fresh-context 规则对照样本；在当前规则下均选择 C（不询问授权，直接实现或派发）。
- 边界复测来源：首轮三态候选把“直接开始”视为拒绝计划，只有 4/5 选择 B；收窄为“拒绝必须明确提及计划，普通催办不算拒绝”后，五个 fresh-context 文案微测均选择 B（询问授权并结束）。
- 用户澄清来源：显式授权仍是必要门禁；缺陷是从未询问而静默执行，不是应取消门禁。
- 修复后验证来源：对按最小修复修改后的真实 `skill-overrides/writing-plans/SKILL.md` 完成 fresh-context 复测（见“VERIFY GREEN”）；修改后的 Skill diff 已通过 `git diff --check`。

## Production 可达性分类

**production 可达（正常入口）**。Pi 启动时会发现 `writing-plans` Skill 并把其 name/description（第 3 行宽触发 description）放入系统提示；这不是测试专用、死代码或仅文档路径。模型判断任务匹配该 description 后，使用 `read` 读取完整 `SKILL.md`——metadata 暴露只保证模型知道该 Skill 存在，并不保证自动读取完整正文。读取后的正文规则直接约束 agent 在正常任务会话中的决策和执行/派发时机。

## 完整加载与决策调用链

1. 用户提出复杂、多步骤、跨模块依赖或关键不确定任务。
2. Pi 启动时已发现本 Skill 并将其 name/description 放入系统提示；模型判断当前任务匹配 description 后，使用 `read` 读取完整 `SKILL.md`（metadata 暴露不保证自动读取；宽触发只影响匹配判断，不代表计划授权）。
3. agent 按读取到的正文进入“用户授权门禁”，在开始声明、文件结构分析或写入 `docs/plans/` 前判断用户授权状态。
4. 修复前第 14 行仅把明确要求/同意映射为进入计划产出流程。
5. **首个偏离点：**修复前第 16 行把所有“未获授权”一并映射为“跳过计划创建，直接按适用规则执行”，没有区分明确拒绝与尚未表态。
6. 对尚未表态用户，agent 因而直接进入 TDD、subagent-dispatch、安全和项目规则，可能实现或派发；授权询问从未发生。

## RED 结果

- 当前规则下，五个 fresh-context 规则对照样本为 **5/5 选择 C**：不询问授权，直接实现或派发。
- 这证明未表态分支被 production 可达的正常入口静默解释为跳过计划，而非一次性询问。
- 三态候选的首轮边界测试为 **4/5 选择 B**，因为一个样本把“直接开始”误判为拒绝计划；该候选仍为 RED，不能采用。
- 收窄拒绝定义后，五个 fresh-context 文案微测为 **5/5 选择 B**：对未表态主动询问一次并结束当前轮次；这定义了本修复应达到的 GREEN 行为。

## 最小修复

仅修改 Skill 正文的授权状态机，保持 description 宽触发职责不变：

- 明确同意编写计划：进入既有完整计划产出流程。
- 明确拒绝且拒绝明确指向计划本身（如“不要写计划”“跳过计划”“无需计划”）：跳过计划并按其他适用规则执行。
- 未明确同意也未明确拒绝：主动询问一次计划授权并结束当前轮次；不得开始声明、分析文件结构、写计划、实现或派发。
- “直接开始”“尽快动手”“别等”“不要解释背景”等普通催办不构成授权或拒绝。

## VERIFY GREEN（修改后真实 Skill）

按上述最小修复修改 `skill-overrides/writing-plans/SKILL.md` 授权状态机后，对修改后的真实 Skill 完成 fresh-context 复测：

- **未表态样本 5/5 选择 B**：五个 fresh-context 样本均主动询问一次计划授权并结束当前轮次；未开始声明、分析文件结构、写计划、实现或派发。
- **明确同意样本选择 A**：进入既有完整计划产出流程。
- **明确拒绝样本选择 C**：跳过计划创建，按其他适用规则执行。
