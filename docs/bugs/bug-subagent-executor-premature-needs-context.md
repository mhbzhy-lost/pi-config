# Executor 在合同信息完整时提前返回 NEEDS_CONTEXT

## 现象

Executor 收到包含目标、文件、验收条件和命令的完整合同后，完成了首个 RED/GREEN 修复，但未执行剩余独立测试任务，最终返回 `NEEDS_CONTEXT`。Supervisor 显示失败原因为验收条件未满足，而非缺少输入或工具错误。

## 影响范围

影响范围较大的多步骤 executor 任务。本次导致狼人杀服务端 Task 5 的核心竞态已修复，但序列化边界、并发投票和阶段序列测试需要再次派发，增加编排与复验成本。

## 复现步骤

派发一个含多个相互独立测试子项的高风险合同。Executor 完成首个逻辑修复和全套测试后，在仍有明确待办且剩余时间充足时报告“其余合同测试未完成”，并以 `NEEDS_CONTEXT` 结束；Acceptance gate 随后因对应 criterion 为 not-satisfied 拒绝。

## 根因

Executor 将“任务范围尚未执行完”错误分类为“缺少上下文”，没有使用合同中已有的要求继续工作，也没有指出任何具体缺失决策。较低思考档位下，单次合同包含多种并发测试设计时更容易提前收束。

## 修复方案

短期把剩余工作按互不重叠的写路径拆成更小合同并行执行，每个合同只负责一种测试文件和一组验收条件。长期应在 executor 完成协议中校验：只有明确列出缺失信息和阻塞问题时才允许 `NEEDS_CONTEXT`；否则未满足 criterion 必须继续执行或报告失败。

## 验证方式

分别派发单文件的小合同，确认 executor 完成全部要求并返回 completed；再验证合并后的完整测试套件通过。运行时层面增加一个合同完整但多步骤的回归任务，确认不会无理由提前返回 `NEEDS_CONTEXT`。
