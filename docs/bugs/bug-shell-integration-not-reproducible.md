# Bug：Pi Shell 集成依赖仓库外手工修改

## 1. 现象

当前机器可以直接执行 `pi` 并加载仓库配置，但该能力依赖手工修改 `~/.zshrc`。新机器
克隆仓库后无法从仓库内容重建同样的运行状态。

## 2. 影响

- 新机器仍会使用 Pi 默认配置根，无法发现 `openai-idealab`。
- `--no-skills` 白名单边界依赖未记录的 Shell 注册步骤。

## 3. 稳定复现

- 在空 `HOME` 下克隆仓库并安装 Pi。
- 直接执行 `pi --list-models openai-idealab`。
- 因 `~/.zshrc` 未加载 `scripts/pi-shell.zsh`，模型不可见；仓库内也没有统一初始化入口补齐该步骤。

## 4. 证据

- Shell 注册行只存在于当前用户的 `~/.zshrc`，不属于仓库。
- 仓库 README 要求手工 `source scripts/pi-shell.zsh`，但不会持久注册。

## 5. 根因

初始化流程只关注运行时配置和测试，没有把“修改用户 Shell 启动文件”建模为仓库维护的
幂等安装步骤，导致可工作的机器状态无法由版本化内容重放。

## 6. 修复与验证策略

- 在仓库根新增 `init-pi.sh`，作为新机器唯一初始化入口。
- 脚本固定安装 Pi `0.80.6`、初始化 submodule，并以受控区块幂等注册 zsh 集成。
- 脚本最后运行单元测试、doctor 和真实 RPC 集成测试。
- 在临时 `HOME` 和临时仓库中连续执行两次，断言 Shell 区块不重复、Pi 凭据不被改写且
  外部命令参数稳定。
